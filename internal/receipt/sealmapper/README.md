# Seal AI 票据映射

`Map` 使用调用方提供的 `documentId` 和 `documentSN` 标识一条报销明细；同一明细的多张附件应共用这两个值。结构化发票的 `sourceInvoiceId` 则由「报销明细记录 ID + 附件 token」生成。调用方先上传原附件，再传入上传响应。上传响应必须带完整附件元数据，文档才会加入真正的 `ATTACHMENT` 字段；缺元数据就停止提交，不再把附件 ID 当作文本替代。文档只包含已识别的事实；只有发票号、币种、含税金额、买卖方以及已上传附件 ID 齐全时，才附上结构化海外发票。缺项时仍可提交普通文档和原件供 Seal AI 审核，但不伪造发票字段。

这个包只负责纯数据映射。飞书记录读取、附件上传、HTTP 提交和回调处理由各自适配器及上层编排负责。
## 多票聚合

`MapBatch` 接收 `internal/receipt/aggregate` 的中立单据，给每张票的字段加序号前缀并组成一份 SealAI 单据；台账查重候选作为审核证据字段一起发送。原件必须先上传 SealAI，上传结果按附件 token 传入。缺少结构化发票的必填事实时仍保留 OCR 字段和原件，不编造币种或金额。
