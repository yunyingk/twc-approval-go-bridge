# 原生审批表单来源与计划预览

2026-10-05，承接 `9cb4676`。上一阶段只核对当前 AI 证据及模板元数据；本阶段接入类型化 Base 来源、共用准备门禁和经过表单校验的计划摘要。真实建单、审批上传和人工结果交付尚未启用。

## 实施选择

`feishu/base.ApprovalFieldsSource` 按所选配置的物理字段 ID 读取实时 schema，再按当前字段名称获取原始 JSON 值。记录查询显式使用 `user_id_type=open_id` 和 `text_field_as_array=true`；不使用通用显示文本转换器处理金额、人员或关系。接口参数已核对[飞书记录读取文档](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/get)及仓库固定版本的官方 Go SDK。既有审核的默认查询行为不变。

- 金额使用 `json.Number` 和现有精确十进制规则，保留超过 2^53 的值；money 必须有明确币种或同源币种字段。日期只接受类型 5 的毫秒时间戳，分组按显式时区取 day/month。
- 项目等关系使用当前字段的目标 table 和真实 record ID；同名项目不合并，显示名修改不改变关联身份。多关系值不取第一项。文本、单选、数字、人员、日期、复选框支持相应分组类型，公式、查找引用和多选不做隐式推导。
- 流水字段只能来自明确的单笔原生关联。缺失、多笔或错误目标分别阻塞，不猜分摊或求和。同批重复引用的流水只读一次；流水权限失败保留安全分类。
- 人员从来源应用 open ID 映射到目标应用范围；跨应用必须逐人有显式映射，缺失或多个人映射为同一目标不通过。这里验证返回格式和配置映射，不声称已经核验目标企业的员工/发起权限。
- 附件输入识别类型 17 和实际 Base 文件引用，但返回 `approval_upload_required`；没有上传调用，也没有把 Base token 填入原生 `attachmentV2`。

`app/approval.PreparedSource` 把类型化输入和已有 `ReviewGate` 组合成共用 `Source`。只从唯一且当前的已存审核结果填入 decision/comment；Base 的 AI 显示列不能代替它。先读表单值，再核对审核事实，对可能进入计划的行重读表单值；观测到金额、分组、人员或绑定变化则报告 `source_changed`。一行阻塞就停止整个显式选择，不能偷偷提交剩余子集。

每行额外保存 `source_version`，摘要涵盖来源应用、物理字段、人员映射和分组/时区等绑定；改变绑定参与计划 UUID，稳定的 Base/Table source scope 保持不变。该字段为 omitempty，原有无此字段的计划保持兼容。多次 Base 读取仍非事务，也没有远端条件锁；审核只涵盖原请求包含的事实，新增表单字段不是自动获得了 AI 审核。

`preview-approval` 的 manual 配置现在读取上述输入。AI、来源和目标模板都可用时，按全部所选行分组，构造完整中立计划并通过实际 gateway 验证实时必填字段/类型。任一组失败不返回部分计划。输出仅含 UUID/revision、成员 ID、分组轴和安全问题；业务值、评论、人员显示信息、原件及远端错误体不进入诊断 JSON。`creation_available` 仍为 false，命令不领取成员、创建状态、上传、通知或建单。
