# 共用人工审批：分组、成员预约与 UUID 恢复

2026-10-05，承接 `f92e57c` 的[实现约定](../native-approval-implementation.md)。本阶段完成 T6 的共用用例与单主机状态约束，服务运行链路尚未启用人工审批。

## 改动与原因

- `core/approval` 定义平台中立的行、精确业务值、身份范围、审核版本和冻结计划；没有飞书 SDK 或控件协议。分组轴与允许的 AI 建议必须显式传入；日期分桶及物理字段读取交给来源适配器。
- 每行要求审核已完成，`document_id` 对应该来源/明细，审核 revision 等于当前 revision。AI 列有值或曾交付不作为有效性证明；两份企业样本在上一阶段已发现历史快照变化，不能直接作为当前人工审批输入。
- 按排序后的成员、审核引用、业务值、分组及目标模板/配置产生稳定内容 UUID。相同选择顺序变化不生成新身份；金额、来源版本、目标和配置变化会产生新计划。
- `app/approval.Prepare` 只读取及校验；首次 `Submit` 重新准备所选成员，变化则停止。外部建单前 `BeginApproval` 在同一原子写入中保存完整计划和全部预约，避免只保存去重版本但同一明细进入两个不同批次。
- 同一计划已有映射时返回历史映射；未确认映射要求对账，不盲目重发。调用成功但保存失败仍保留建单前 UUID。调用者取消不阻止结果落盘。
- `Reconcile` 查询已存 UUID，独立于当前来源读取/模板选择；校验目标、模板、发起人及实例绑定，保存真实观察历史。先确认的结果不能被创建错误覆盖，旧查询不覆盖后发查询，终态不能退回 pending。
- 文件状态库按来源范围持有 OS 锁并原子替换，适用于单主机持久卷；读取不新建文件。冻结计划、已确认实例 ID、创建时间和观察历史不可改写；未知状态不能改成释放预约的失败状态。状态只保存安全错误分类，不保存上游报错原文。

## 保留的边界与下一步

提交前重核不是远端事务锁，核对与创建之间仍可能发生编辑；冻结计划不等于已经锁定 Base 或金额。查询先后以本地请求开始时间控制，本阶段没有外部事件序号。审批通过、拒绝、撤销或删除均继续预约；结算/合法分摊/撤销释放需独立业务策略，不删除状态解锁。

继续接入实时模板 gateway，再补显式业务配置、真实 Base 来源和只读预览。当前模板对桥接应用不可读、审批身份范围未证实，真实发起人/审批人映射仍未配置；不可自动回退旧应用。审批附件上传及复用、人工状态交付、Seal `manual-result`、撤回重提、占用与结算仍属于完整目标的未完成项。

## 状态迁移补充检查

在 gateway 接入 `b74aa27` 后继续检查状态边界：仅禁止 `unknown → failed` 不够，后续代码若先将未知重置为 submitting，就可能再按“明确拒绝”释放预约。因此状态库显式约束完整迁移：首次 submitting 可进入 unknown/failed/pending/finished；unknown 或 failed 只能保持原状态或通过真实查询进入 pending/finished；pending 可结束，finished 不退回 pending。没有隐式重新领取原计划的路径。
