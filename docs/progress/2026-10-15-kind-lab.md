# 2026-10-15：独立 WSL kind 演练

用户授权在 WSL 搭建测试环境，现有 Docker 业务继续运行，测试不接入真实飞书凭据或单据。版本固定 kind v0.33.0、Kubernetes/kubectl v1.34.11；工具 SHA-256 与官方校验一致，节点镜像采用官方发行摘要的国内镜像。

## 实施

- 私有根目录 `/home/dev/apps/twc-k8s-lab`，独立 kubeconfig（0600），上下文固定 `kind-twc-lab`；只操作该 kind 节点和 `twc-lab` Namespace。节点 CPU 上限 2、内存与 memory+swap 上限 4GiB；只绑定 WSL localhost 随机端口，不改全局 frpc 和业务入口。
- 原 K8s 模板移入共享 base，保留有效注释、单副本和 Recreate；使用 Secret 配置、非 root 用户、受限 Pod 设置、PVC 和现有 HTTP 探针。lab overlay 只使用合成配置，关闭业务触发和连接，移除公网 Ingress。
- 新增 Linux 直接构建／发布入口，共用原 remote-service 的构建和镜像完整性校验；GitLab 模板针对已配置 Docker 的非 root Linux Shell Runner，不要求连接个人 WSL。公司 Runner/ACR/ACK 的真实接入未执行。

## 实施发现

1. Docker 调整 kind 节点内存时必须同时调整 memoryswap；只修改这一个测试节点，不修改宿主机和其他容器。
2. Kustomize 基础目录须与 overlay 分离；Service 合并补丁显式填写 protocol，才能保留固定 NodePort。
3. containerd 给导入镜像生成新的索引；通过读取内容并核对摘要解析到原平台 manifest，而不是放宽校验。辅助镜像也按单平台导出，避免 `kind load docker-image` 引用未下载的其他架构内容。
