# 2026-10-05：明细修改重审与来源生命周期

继续 T4 的版本与恢复工作。用户已授权按计划推进，并要求每阶段清晰提交、保留 Markdown 记录。此次只补明细有效输入的变更触发，不扩展人工审批规则或修改第三方流水。

## 问题与实现

此前只有 OCR 台账交付会排队，修改事由或关联流水不会自动重审；全部附件移除或明细删除会使待送审反复失败，迟到结果也无法按来源生命周期归档。

- 业务 JSON 增加 `resubmit_on_detail_change`，默认关闭，只与 `after_recognition` 搭配；`change_debounce` 默认 10 秒，可配置为 1 秒至 10 分钟。企业文件显式保持关闭。
- 飞书输入适配器仅监听附件、编号、配置的上下文和启用的流水关联；过滤 AI 回写、人工审批及锁定字段。事件确认前持久化，不在长连接回调内读取附件或调用付费接口。
- 共同自动审核保存编辑等待期限、最近 64 个事件 ID 和任务代数，连续编辑合并，重启恢复，旧任务确认不能丢掉审核期间的新变更。实际事实未变则复用已有审核尝试。
- 定义无附件/来源删除的独立业务错误：结束待送审但不删除历史；旧结果仍保存，不写当前明细。飞书记录不存在的 `1254043` 已通过当前项目应用身份对不存在的记录进行 GET 核验，HTTP 200、平台错误码 1254043。权限、网络和不完整台账错误仍可重试；关联流水读取错误不会当作明细删除。
