# 原生审批 gateway：接入共用用例与独立查询

2026-10-05，承接 `200e36c` 的共用审批编排与 `929cbf1` 的实例客户端。本阶段只做代码及隔离 HTTP 联测；没有部署、创建真实实例、上传附件、通知或调用付费 AI。

## 最终改动

- `InstanceClient.TargetScope` 来自显式应用 ID；模板不可读时不回退到另一应用，也不把 Base 人员直接用于旧审批应用。
- `InstanceGateway` 读取实际 ACTIVE 定义，把 API 暴露的表单/节点元数据和本地绑定、自选审批人纳入配置版本。准备、提交前重核及最终创建前均校验该版本，模板或映射变化则停止发送。
- 业务值类型严格对应当前控件：文本、日期、精确数字/金额、人员、审批文件。文件必须提供审批上传的 file code；本阶段没有上传实现。
- 按当前流程节点检查必需自选审批人、真实 node ID、单/多选数量及 open ID 格式，不猜人员或覆盖固定审批节点。节点配置和绑定复制保存，审批人集合排序不改变计划身份。
- 发送一次已有 UUID，创建成功先保存 pending 映射。官方明确参数错误、不支持的流程、停用定义及权限拒绝（HTTP 400）属于未创建；`60012`、`1395001`、未确认错误码、网络/响应异常保持未知。HTTP 与错误码相互矛盾时也不释放预约。
- `InstanceLookupGateway` 与创建 gateway 分开；共用 `LookupGateway` 接口仅保留身份和查询。恢复不需要当前模板、表单绑定、来源读取或 AI 提供方，查询原 UUID 后校验原模板、发起人和应用；SDK JSON 留在适配层。
- 兼容定义客户端的错误在新 gateway 边界转换为安全错误，既有模板工具接口保持原样；共用状态只保存安全分类和数值元信息。

## 验证与证据范围

隔离 HTTP 与真实文件状态联测验证：两行各 14 列、精确金额 `9007199254740993.12`、系统 widget ID、审批 file code、自选审批人；创建响应丢失后保留 unknown，选中新模板或移除创建配置后仍用原 UUID 查到批准状态，创建次数始终为 1。

另验证明确拒绝/UUID 冲突/内部错误/未知码/矛盾 HTTP 分类，模板及绑定变更阻止 POST，文本不能偷偷解释为日期，缺失或错误自选审批人阻止准备，查询错 UUID/模板/发起人/状态被拒绝，切换目标应用在获取令牌前停止，调用方修改配置及审批人排序稳定，上游定义错误原文不暴露。

通过默认及 `no_anthropic` 全量测试、vet、构建，审批核心/用例/状态/适配器 race 检查及 `git diff --check`。测试 API 全为假 HTTP transport；上阶段真实模板只读证据仍见[实例客户端记录](2026-10-05-native-approval-client.md)，不能将此次 fake 联测计入真实人工审批验收。

## 剩余业务与限制

应用范围与 open ID 格式只是边界检查，真实员工归属/跨应用映射仍需显式配置及线上核验；自选范围及模板货币限制由真实接口再次校验。配置摘要只固定 API 暴露的元数据，不能锁住服务端流程，读取与 POST 之间仍有并发窗口；本阶段保存绑定摘要，没有独立原生请求/节点配置的完整审计快照。

明确拒绝的原计划不会自动重发，新计划可重新领取已证明未创建的成员；同一事实/配置恢复后仍需补安全的显式重试入口。未知或已建单成员继续预约，批准/拒绝/撤销/删除都不提供财务释放。
